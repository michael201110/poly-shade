# PolyShade 0.4.0: WebGPU and SGSR2 Compute

## Renderer migration

PolyTrack/PML 0.6.3 supplies its own Three r181 scene, camera and WebGL renderer. Those exports do not include WebGPURenderer. PolyShade now bundles **Three 0.181.2** as a production dependency for an isolated replacement renderer; it does not substitute npm constructors into the game's native object hierarchy.

`src/renderer.js` continues intercepting the game's constructor-assigned `WebGLRenderer.render`. The controller prepares the original logical scene as before, then delegates through `RenderBackends`. On WebGPU, the intercepted main draw is consumed: the native main renderer does not render that frame. A synchronized compatibility scene renders the actual track, cars, shadows and environment through `WebGPURenderer` into a WebGPU HDR/depth target. Native utility/thumbnail renderers are independent.

Only CPU scene descriptions cross this boundary: matrices, geometry attributes, morph weights, colours, material parameters and source texture images. No rendered WebGL image is copied or sampled. Buffer attributes are cloned once and refreshed by version, preventing WebGPU's index/storage alignment from mutating game buffers. Instanced track geometry remains instanced.

A replacement canvas follows the original canvas's drawing-buffer dimensions, CSS rectangle, parent and DPR. The original stays in place for input and becomes transparent only after initialization and several successful warm frames. Both canvases restore on disable/failure. The HTML HUD and panel remain outside the entire 3D/post/upscaling path.

## Backend selection and failure

| Requested mode | WebGPU | WebGL2 |
| --- | --- | --- |
| Native | Native scene resolution (legacy renderScale applies) | Existing native path |
| Reduced | Spatial reduced scene/presentation | Existing reduced path |
| SGSR2 Fragment | Explicitly selects the WebGL backend | Official two-pass fragment path |
| SGSR2 Compute | Official two-pass compute path | Native, with unsupported reason |
| Auto | Compute if initialized; otherwise Native | Fragment if supported; otherwise Native |

Renderer Auto attempts WebGPU. Explicit WebGL retains the reference renderer. Unsupported visible legacy shaders, unknown shader callbacks, unavailable devices and validation failures trigger a sticky session fallback to WebGL. Requested Auto can then use Fragment; explicit Compute falls back to Native rather than being mislabelled. Compute compilation failure can retain WebGPU with Native reconstruction. Device loss invalidates temporal state and immediately restores the input canvas; the next intercepted game draw uses WebGL. There is no per-frame retry loop.

## Scene and shader compatibility

MeshBasic/Lambert/Phong/Standard/Physical materials map to corresponding node materials. The layer preserves vertex colours, images/maps, instancing, car paint colour/roughness/metalness, emissives, alpha/transparency, depth, blend and polygon-offset flags. CPU-authored sky environment textures upload directly to the GPU renderer's own PMREM path. Source material objects and brake handles stay owned by PolyTrack. The native two-colour car-pattern callback has a node equivalent that retains its live pattern/secondary-colour uniforms; both Color and Vector3 colour representations are handled explicitly. Native ambient/hemisphere contributions are copied after preset application, instead of silently losing the game's base fill.

PolyShade's legacy shadow-safety wrapper is unwrapped through its existing snapshot table for callback inspection. Known CSM hooks are replaced by Three's supported **CSMShadowNode**, with one illumination sun and three shadow cascades. Singular/projective native shadow proxy meshes are omitted; actual geometry casts GPU shadows. GPU shadow bias is separately calibrated to avoid road acne/stripes. Node contact shadows preserve grounding in overhead shade. Native spot/point lights, including real brake spill, remain lights rather than emissive-only substitutes.

The procedural sky and broad cloud noise are WGSL/node implementations of the existing stylized gradient, disc and cloud functions. Contact opacity and procedural roughness detail have node equivalents. PolyShade-owned fullscreen GLSL effects have separate WGSL implementations: depth-based SSAO and bilateral filtering, bloom, cloud-aware sun visibility, rays, full-internal-resolution volumetric sunlight, aerial perspective, colour grading/tone mapping, relative-camera motion blur, lens ghosts, FXAA and sharpening.

The WebGPU port retains the visual intent/settings, not pixel-identical shading to WebGL. Different CSM filtering and material lighting can change appearance. Scattering remains a screen-space approximation with limited offscreen occlusion information.

## Frame and resource architecture

```
PolyTrack CPU scene/camera
  → compatibility scene + node materials
  → internal HDR scene + depth (WebGPU)
  → static depth-reprojected velocity
  → independently moving car/wheel/morph velocity overlay
  → internal AO/bloom/visibility/rays/volume/grade
  → SGSR2 Convert compute
  → SGSR2 Upscale compute → native RGB + next YCoCg history
  → previous geometry update
  → native presentation/colour-space conversion
```

All passes share the actual GPUDevice returned by Three. The pinned private attachment lookup, GPUCanvasContext access and scene-pass timestamp hook are isolated in `src/rendering/webgpu/three-adapter.js`. This adapter is necessary to feed Three-owned render targets to explicit WGSL pipelines without an image bridge; upgrades require revalidation.

| Resource | Format | Usage |
| --- | --- | --- |
| Scene colour | RGBA16Float | Three-owned render attachment + sampled texture |
| Scene depth | Depth32Float | Three-owned depth attachment + sampled texture |
| Signed velocity | RGBA16Float | Render attachment + texture binding |
| AO, bloom, rays, volume, graded colour | RGBA16Float | Render attachment + texture binding |
| Convert motion/depth/ColorMax | RGBA16Float | Storage write + texture binding |
| Packed YCoCg | R32Uint | Storage write + texture binding |
| Local history rejection | R32Float | Storage write + unfilterable texture binding |
| Native YCoCg histories A/B | RGBA16Float | Storage write + texture binding |
| Native reconstructed RGB | RGBA16Float | Storage write + texture binding |
| Previous geometry | RGBA16Float | Render attachment + texture binding |
| Post/compute uniforms | Buffer, 736 / 80 bytes | Uniform + COPY_DST |

Histories and intermediate textures persist. Resolution changes replace only affected targets. Modes/settings/scene/camera changes invalidate logical history. Disabled feature targets may remain cached for reuse, with a bounded number of named targets. Inactive WebGL post targets are released when WebGPU takes over, then rebuilt only on fallback. Source texture disposal releases corresponding GPU copies, including replaced sky environments. The established shadow-caster cache is reused with a CSM-node light adapter; unjittered camera/caster/morph changes invalidate it. Native canvas resolution stays unchanged at 100%, 77%, 67%, 59% and 50% internal scale. SGSR2 output bypasses FXAA and reaches final presentation in linear colour.

Bind groups never sample their writable render target, including unused declared entries. R32Float rejection is kept separate from filtered AO. These distinctions resolved validation failures encountered during development.

## Qualcomm algorithm and integration changes

Reference: [official SGSR2 v2](https://github.com/SnapdragonGameStudios/snapdragon-gsr/tree/d926f074bcb9d714e179f1ce0fcb9ee2eeb5074e/sgsr/v2), specifically `glsl_2_pass_cs/sgsr2_convert.comp` and `sgsr2_upscale.comp`. Unmodified originals and the BSD license are vendored. The WGSL port preserves the upstream two-pass structure, packed 11/11/10-bit YCoCg, colour compression/inverse compression, depth clipping, five/nine-tap signed Lanczos reconstruction, variance box, history clamp and update weighting. Both dispatch **8×8×1** workgroups with bounds checks for odd dimensions.

Integration differences:

- Bounded textureLoad gathers replace GLSL textureGather while retaining component order.
- Full signed NDC motion replaces the upstream encoded-UNORM/zero-vector inference.
- WebGPU depth is 0..1 and texture UV is top-down; current-minus-previous motion uses NDC Y-up. Reprojection consistently converts Y and compensates actual current/previous pixel jitter.
- Existing TemporalState feeds both backends. Still-camera detection compares unjittered VP, so jitter does not suppress stationary history weighting.
- Previous geometry stores linear depth, car coverage, moving/reset coverage and validity. Convert checks reprojection bounds, expected previous depth, object validity and a 3×3 moving-coverage neighbourhood. Finite differences supply compute depth tolerance.
- Rejection has its own R32Float texture, leaving upstream ColorMax alpha intact. Rejected pixels force current reconstruction; unaffected pixels keep upstream temporal weighting. Global history is not weakened to hide moving-car ghosts.
- A signed near-zero divisor guard preserves Lanczos's negative lobes. Replacing a negative weight sum with positive epsilon was caught by a constant-colour GPU regression test and corrected.
- Sky geometry history uses a consistent far sentinel; static track geometry never receives a per-object velocity draw.
- Car velocity includes rigid body/wheel matrices and up to eight position morph targets, with current and previous morph weights evaluated on the GPU.

Disabling Post processing selects Native and skips optional effects, while retaining required tone-map/presentation. CSM/material compilation occurs with an unjittered camera before the first temporal frame, since CSM initialization can update projection. The mod restores the camera projection after every frame, including exceptions. Native PolyTrack camera matrices are not jittered by the GPU mirror.

## Diagnostics and profiling

Diagnostics report actual renderer, requested/active upscaler, internal/output dimensions, temporal validity/reset reason/jitter, dispatch counts and workgroup dimensions. Views include low-resolution colour, depth, static/car/combined motion, jitter, history validity, rejection, previous history and native comparison. Debug presentation does not overwrite history or replace combined velocity with a diagnostic-only field.

Only the active backend profiles GPU passes, avoiding reference WebGL query activity during WebGPU measurements. GPU timestamps sample actual Three scene/shadow passes and raw passes every twelfth diagnostic frame. Three/pass durations are summed without CPU submission gaps. Reports include median/p95 scene, static/car velocity, post stages, Convert, Upscale, reconstruction, presentation and total GPU work. A three-slot asynchronous timestamp buffer ring prevents waits. Profiling disabled means no query resolve/map activity. Timestamp metadata readback is diagnostic-only; colour/depth/velocity never read back in normal rendering.

CPU rendering submission timings remain separate. Total GPU work here is the sum of measured passes, not presentation latency or a gameplay FPS measurement.

## Compatibility limits

- This is a WebGPU graphics/compute implementation, without a WebGL image bridge. Chromium/Edge GPU policy and driver support still control device availability.
- Legacy arbitrary ShaderMaterial, unknown vertex callbacks, skinned meshes and compressed source textures need specific adapters and trigger fallback. Native CSM, PolyShade shadow safety/roughness, ordinary material maps and game position morphs have explicit support.
- Opaque rigid/morphed cars have independent motion. Moving instances, skinning and transparent ghost motion are not independently reconstructed; translucent ghosts retain rendering/alpha but can trail temporally.
- Legacy singular/projective helper meshes are omitted, including any skid helpers using that representation; ordinary textured smoke meshes still render. The WebGL reference retains its historical far-object artifacts.
- Screen-space shafts/volume cannot see offscreen occluders. The generated environment represents sky lighting, not full dynamic world reflections.
- WebGPU uses single-sample scene depth. The legacy Scene MSAA setting applies to WebGL; temporal reconstruction/FXAA provide the GPU presentation antialiasing.
- Shader/pipeline initialization and the first environment/shadow allocation can cause startup work; the original renderer remains visible through warmup. No claim is made that every game-side freeze or driver stall has been eliminated.
- A pinned Three renderer increases bundle size (approximately 3 MB unminified). Native game objects/material handles are never replaced with this dependency's objects.

At 59%, Compute's median GPU work is 5% below native WebGPU (2.490 versus 2.621 ms). At 50% it is effectively tied, and 67–100% cost more. Compute is not universally faster than Fragment on this T500; native is a sensible choice for this light scene. Reduced scene work alone does not repay reconstruction cost at every scale. These measurements do not demonstrate that long gameplay freezes have been eliminated.

All 67 unit tests, live/replay reference verification, fragment temporal inputs, the standalone compute regression, WebGPU verification and the benchmark/lifecycle checks passed. Normal WebGPU validation/page errors: zero. Profiling-disabled buffer maps: zero. Deliberate device destruction restored WebGL and the original canvas.

The stationary-camera road probe rejects newly revealed car pixels (rejection 1) while an untouched road probe retains history (rejection 0), with global history still valid. Static thin-marking variance before/after moving-car rejection is identical: 0.00000240571. A camera-following car has approximately zero relative velocity while the road moves. Synthetic probes use a controlled 60 Hz temporal clock to exclude diagnostic readback latency; this is not a performance test. Swarm coverage tests 160 synthetic opaque plane movers, 147 visible, rather than 160 fully detailed race cars.

Summer 2 replay captures show correctly coloured cars, native DOM text and no detached far-object black polygons in the captured views. Still images cannot establish the absence of all temporal shimmer or ghosting. Lower scales soften distant barriers and thin details; fine road patterns/aliasing remain visible, and transparent ghosts lack independent velocity. Moving-road rejection is numerically verified, but dense real swarm motion and long driving sessions still need broader visual assessment. See the saved reports for the precise test conditions and limitations.
