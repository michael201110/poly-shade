# PolyShade 0.5.5 — moving 4K GPU investigation

This pass addresses two measured full-resolution costs: the 64-tap sun-ray integration and the scale calculation repeated in every SGSR2 output invocation. It does not change scene resolution, SGSR2 history format, car/replay interpolation, camera timing, physics, or training behavior. Swarm shadow work remains deferred.

## Test setup

- PolyTrack 0.6.3 in a fresh headless Edge profile; 3840×2160 canvas, device scale factor 1.
- NVIDIA T500, driver 573.91; WebGPU requested with `powerPreference: "high-performance"`.
- Golden Hour/cinematic profile and the same moving 22.595 s champion replay for baseline and candidate. A single green replay car was used to measure ordinary moving gameplay without swarm scale effects.
- Each GPU pass distribution has 30–53 samples depending on whether the pass ran during the capture window. Values below are timestamp-query medians in milliseconds. Browser frame intervals are a separate measurement.
- The viewport variable was cleared before the clean verification suite. Earlier failed test invocations inherited the benchmark's 4K viewport and PolyBot injection; those failures were harness configuration errors and passed after cleanup.

## Native 4K path

The baseline moving run measured 105.58 ms GPU time at p50 and a 116.6 ms browser frame interval at p50. With quarter-resolution rays, the same path measured 89.72 ms GPU time and 99.9 ms frame interval. The strongest pass delta was the ray integration itself.

| Pass | Full-resolution rays | Quarter-resolution rays | Delta |
| --- | ---: | ---: | ---: |
| Scene | 34.34 | 33.62 | −0.72 |
| Static velocity | 3.93 | 3.87 | −0.07 |
| AO | 5.96 | 5.96 | 0.00 |
| AO horizontal + vertical | 5.96 | 5.90 | −0.07 |
| Bloom and blur | 1.77 | 1.70 | −0.07 |
| Sun rays | 19.46 | 1.84 | **−17.63** |
| Grade | 29.23 | 29.10 | −0.13 |
| Finish | 7.93 | 7.73 | −0.20 |
| Total | 105.58 | 89.72 | **−15.86** |

The ray shader integrates 64 aperture-mask samples for each output pixel. At 3840×2160 that is about 531 million logical samples per frame. Quartering both target dimensions reduces the ray integration target to 960×540, or about 33 million logical samples. The grade pass already performs a nine-tap ray softening filter whose radius is derived from the ray texture dimensions, so its screen-space footprint remains consistent. Its full-resolution sample instructions remain; the source texture is now 16 times smaller.

The captured frame showed a mean RGB difference of 0.046 on an 8-bit scale; 99% of pixels differed by at most one channel level. Pixels differing by more than eight levels were below 0.07% in the compared capture. This supports the intended use of a smaller target for an already softened light-shaft effect. The ray buffer's sampling is lower-resolution, so this is not a bit-identical intermediate image.

Scene rendering (33.62 ms), grading (29.10 ms), and AO plus its two depth-aware filters (11.86 ms) remain the largest native costs. At 50% render scale, scene time is about 8.45 ms—roughly one quarter of native—showing that scene shading is largely pixel-rate limited. Grade likewise falls from about 29 ms at native to about 6.4 ms at half resolution. The fixed 4K finish pass remains about 7.7 ms. This is a GPU throughput limit, not replay or main-thread CPU work. At 89.72 ms p50, this build is still far from 60 FPS (16.67 ms budget) or 45 FPS (22.22 ms budget) at native 4K on the T500.

## SGSR2 at 50%

The output and both temporal history textures remain full-size RGBA16F targets. The upscale dispatch still writes 8.29 million pixels. Its 8×8 workgroup decodes a shared packed YCoCg footprint, samples the converted and history textures, reads rejection state, and writes both output and history. Approximate logical image traffic is several hundred megabytes per frame: each RGBA16F full-resolution write is about 66 MB, before the history and converted texture samples. These are logical accesses, not measured external-memory transactions; cache reuse changes physical traffic.

| Experiment | SGSR2 upscale p50 | Delta | Result |
| --- | ---: | ---: | --- |
| Baseline 8×8 kernel, same-harness repeat | 39.26 ms | — | Baseline |
| Hoisted scale uniform | 38.21 ms | −1.05 ms (−2.7%) | Kept |
| 16×8 workgroup, 8×8 baseline otherwise | 37.68 ms | −0.72 ms vs quarter-rays 8×8 run | Discarded; below the ~1 ms priority threshold |

The hoisted term is `min(20, pow((displayWidth/renderWidth)*(displayHeight/renderHeight), 3))`; render dimensions are constant for the frame, so it is now computed once on the CPU and passed as a uniform. The operation is mathematically unchanged. A captured-frame comparison had a mean RGB difference of 0.089/255, with 99% of pixels differing by no more than one channel level.

The quarter-resolution ray target also reduced the 50% path's rays pass from 5.11 ms to 1.11 ms (−4.00 ms). Its measured GPU total was 74.91 ms at baseline and 67.90 ms with both kept changes. The upscale pass remains about 38.4 ms and is still the dominant SGSR2 bottleneck. The wider-workgroup experiment did not clear the time-box threshold. The selected WebGPU adapter exposes `shader-f16`, but no f16 math change is included: using lower precision in the temporal filter could alter history stability and needs a separate visual and temporal error study before it is worth shipping.

## Verification

Successful clean-environment commands:

- `npm run check` — 94 tests passed.
- `npm run verify:webgpu`
- `npm run verify:visual`
- `npm run verify:upscaling`
- `npm run verify:4k`
- `npm run profile:swarm` with one full champion replay at 4K/50%.

The first attempts at `verify:webgpu`, `verify:visual`, and `verify:upscaling` inherited `POLYSHADE_VIEWPORT=3840x2160` and `POLYBOT_ROOT` from the profiling shell. After clearing those variables, each command passed. The existing 0.5.4 release bundle was restored after test builds; 0.5.5 has its own versioned output.

## Remaining work

The current native costs point to the next large wins: scene material/fill work, the grade shader's per-pixel texture reads and color transforms, and AO's 16 depth-reconstructed samples plus two blur passes. The SGSR2 upscale still needs a larger bandwidth or algorithm-layout improvement. Further f16, history packing, or intermediate fusion should be measured against temporal stability and image error before release. No swarm shadow changes are included.
