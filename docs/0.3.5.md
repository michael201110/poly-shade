# PolyShade 0.3.5: SGSR2 Fragment

## Architecture and controls

The inspected PolyTrack 0.6.3 runtime uses **Three.js r181 / WebGLRenderer**. PolyShade discovers those classes from PML; it does not bundle a second renderer. npm Three r180 remains a development-test dependency. See [the original pipeline inspection](sgsr2-pipeline.md).

The integrated path is:

1. Save the game's camera projection and inverse; apply Halton (2,3) subpixel jitter.
2. Render the existing scene once into reduced-resolution HDR colour + depth, without scene MSAA.
3. Reconstruct camera/static-world velocity from depth. Overlay existing rigid-car/wheel proxies on that fullscreen field, depth-tested against the actual scene depth. No static track geometry velocity rendering is added.
4. Run the existing AO, bloom, atmosphere, shafts, optional motion blur and colour-grade/tone-map logic. SGSR2 uses a half-float **linear, tone-mapped** internal-resolution grade target, avoiding an additional 8-bit intermediate.
5. Execute Qualcomm's Convert and Upscale fragment shaders into native-resolution ping-pong colour history, with additional local depth/coverage history rejection.
6. Save low-resolution geometry history after its previous-frame contents have been consumed.
7. Use the existing final colour-space/presentation shader at native resolution. FXAA is skipped during SGSR2; user-selected sharpening remains available.
8. Restore the camera matrices and renderer state even on failure.

The canvas dimensions and HTML HUD never change with internal scale. Main-canvas rendering only is reconstructed; offscreen utility scenes and XR rendering pass through. Native mode retains the existing pipeline, including the legacy 100–150% supersampling control under Quality.

Under **Upscaling**, select **Native**, **SGSR2 Fragment**, or **Auto**. Native remains the default; Auto selects Fragment when WebGL2, renderable half-float targets and depth textures are available, otherwise Native. Choose Native/100%, Ultra Quality/77%, Quality/67%, Balanced/59%, Performance/50%, or Custom/50–100%. Reduced resolution is explicitly labelled a bilinear benchmark mode, not SGSR2.

**SGSR2 Compute is unsupported.** Selecting it falls back to native 100% and displays the reason. There is no WebGPU renderer, WGSL port, compute dispatch, shared WebGPU resource path or emulated compute backend in this release. Temporal state/backend selection are separate modules so a future renderer can supply a separate backend without relabelling this WebGL implementation.

## Inputs and conventions

| Input | Producer / representation |
| --- | --- |
| Colour | Existing grade shader, internal-resolution `sgsr-input`, RGBA16F linear tone-mapped RGB |
| Depth | Existing `scene.depthTexture`, unsigned-int OpenGL depth, 0 near / 1 far |
| Combined velocity | Fullscreen depth reprojection plus car proxies, internal-resolution RGBA16F |
| Velocity XY | Signed **current minus previous unjittered NDC** motion; no 64-pixel blur clamp |
| Velocity Z | Tracked foreground coverage, motion and per-object history-invalid flags |
| Velocity W | Predicted previous **linear view depth**, including previous object transforms |
| Colour history | Native-resolution `sgsr-history-a/b`, RGBA16F, ping-pong |
| Geometry history | Internal `sgsr-geometry`: previous linear view depth, foreground coverage, moving-foreground coverage, validity |
| Jitter | Halton (2,3), ±0.5 internal pixels, phase count `ceil(8 * outputWidth² / internalWidth²)` |
| Camera data | Actual current and previous rendered jittered VP, current inverse, original projection/inverse and previous inverse projection |
| Temporal data | Frame delta, sequence, camera-still count, reset reason and validity; the two-pass FS algorithm has no frame-delta/exposure-ratio uniform |

For static pixels, current depth is unprojected with the **current jittered inverse VP**, then projected with the **actual previous rendered jittered VP**. The corresponding current/previous jitter offsets are removed to express stable NDC velocity. For rigid cars, the proxy uses `previousJitteredVP * previousModelMatrix * localPosition`; each wheel/body part retains its own transform. Current rasterization still uses the current jittered camera. An infinite sky direction ignores camera translation while retaining rotation.

In UV form:

```text
velocityNDC = 2 * ((currentRenderedUV - currentJitter/internalSize)
                - (previousRenderedUV - previousJitter/internalSize))
previousRenderedUV = currentRenderedUV - currentJitter/internalSize
                   - velocityNDC/2 + previousJitter/internalSize
```

Signed floating-point motion avoids the false velocity introduced by biasing zero around 0.5 in FP16. The input adapter therefore reads raw signed motion instead of UNORM-decoding it; this changes input representation, not the reconstruction filter.

Opaque cars are discovered through the game's native BrakeLight material and their rigid descendants. Opaque replay/training-named car meshes are included for SGSR2 without changing native materials. Other compatible rigid movers can opt in through `mesh.userData.polyShadeDynamic = true`. Previous source matrices are captured after the main scene has updated them. Source discovery is throttled and uses a Set rather than quadratic duplicate searches.

## Local disocclusion, not a global history reduction

Convert reprojects each pixel into previous **jittered** geometry history using the combined motion field. It compares predicted previous view depth against the stored depth, with relative precision and depth-slope tolerance. It rejects out-of-view samples, invalid geometry history, depth mismatches, road previously occupied by a tracked car, newly exposed/new car pixels and invalid per-object history. Previous moving-object coverage is dilated by one internal pixel in a 3×3 neighbourhood to cover undersampled edges.

The rejection value is carried in Convert's previously unused alpha channel and adds a per-pixel reset to Upscale's history blend. Qualcomm's normal temporal weights remain in use everywhere else. A car spawn, geometry replacement or independent teleport marks that object's history invalid locally rather than resetting the track's entire history.

Global colour and geometry history reset on resize, internal-scale/mode/jitter/settings changes, scene/camera/projection changes, large camera cuts, long frame gaps, visibility changes, game load, standard restart/menu keys and recognized run/reset UI actions. Projection jitter restarts with the history. Camera/transform checks also cover programmatic camera movement. Home disables/restores the mod; End controls panel visibility independently.

## Debugging and profiling

Upscaling debug views expose low-resolution colour, depth, static velocity, car velocity, combined velocity, jitter, global history validity, **per-pixel history rejection**, previous colour history and a native comparison. Velocity R/G visualize signed horizontal/vertical motion around 0.5; blue shows magnitude. History validity is green/red; rejection is green for retained history and red for rejected history. Projection jitter can be disabled for diagnosis. Changing a debug view invalidates history; returning to Final restores ordinary reconstruction.

Enable Detailed diagnostics and Per-pass profiling to see scene, static/car velocity, `sgsr2`, geometry-history and other pass timings. The SGSR2 timing groups the two official reconstruction passes; geometry-history bookkeeping is measured separately. Whole-pipeline GPU queries and individual pass queries use different frames to avoid nested timer queries. Availability is polled asynchronously; no synchronous GPU readbacks ship in the mod. Normal operation retains only the existing sampled whole-pipeline timer, not per-pass profiling.

## Verification

Verified on 15 October 2026 in a fresh headless Microsoft Edge profile with the real official PML 0.6.3 game, NVIDIA T500 via ANGLE/D3D11, 1280×720 output. The tests do not alter the user's browser session. Public replay API requests are bridged only in the development harness.

- Native rendering passed after the input stage and again after reconstruction, mode changes and resize.
- GPU velocity checks cover followed car vs moving road, fixed-camera independent car motion, jitter-only motion, occluding walls, camera teleports, scale changes and explicit reset.
- The stationary-camera disocclusion test retains the normal still-camera interpolation contribution of **0.3**, keeps global history valid, rejects newly exposed road with mask **1**, and retains the static-road control with mask **0**. The revealed road matches its clean current-frame tone-mapped RGB, rather than retaining red car colour.
- A thin static marking is measured with matching jitter phases, both with and without a moving foreground car; the marking control retains history. Both cases measured temporal variance **0.0000923448** in the same 32×32 region over 16 sampled frames after 32 warmup frames, with no rejection on the marking control. Synthetic GPU frames use deterministic 60 Hz timestamps so synchronous test draws do not create spurious zero-delta resets. This establishes no added shimmer in that controlled test, not in every gameplay view.
- 160 additional opaque rigid training-named meshes receive their own velocities. A visible distant swarm mesh measured independent horizontal NDC velocity **0.00649643** after a 0.1-unit translation under a stationary camera. Spawning them keeps global static history valid. This is a synthetic swarm test, not a claim that an external training mod or every instanced/transparent swarm representation was tested.
- Resize to 1024×640 and back, Compute fallback, return to Native with temporal targets released, Home restoration, End hide/show and an injected SGSR2 failure all pass. Failure restores the unjittered projection and native 1280×720 output.
- The complete Node test suite passes (63 tests). No PolyShade shader errors or uncaught errors occurred in the successful live runs.

The [input/disocclusion report](verification/0.3.5/temporal-inputs.json) and [benchmark report](verification/0.3.5/benchmark.json) preserve the measurements.

## Visual results and limitations

Native/67%/50% captures and the moving Summer 2 replay were inspected. Car silhouettes and broad barriers remain readable; 50% loses more small detail and thin curb/track features can still shimmer during movement. The local road-ghost regression passes, but it does not establish zero ghosting for every track/material. Static-marking variance is explicitly measured rather than inferred from one screenshot.

Opaque rigid swarm motion is supported and GPU-tested. Geometry below an internal pixel can still flicker or disappear at 50%, and the synthetic swarm does not validate an external training mod. Skinned/morphing meshes, GPU shader deformation, independently moving instances and alpha-blended ghost/particle layers do not have complete independent velocity/reactive-mask support. Static instances correctly get camera motion through depth. Screen-space optics and existing motion blur are composed upstream of reconstruction and may soften it. Subpixel specular changes can also flicker.

The captured native-High-shadow view contains an existing black patch on a distant structure in both Native and SGSR2. This upscaling change does not claim to fix the separate native shadow artifact.

## Upstream fidelity and attribution

The exact official two-pass FS shaders are vendored from Qualcomm commit `d926f074bcb9d714e179f1ce0fcb9ee2eeb5074e`. The source's FastLanczos filter, enabled five-tap kernel (the optional diagonal taps remain disabled exactly as upstream), local depth clip, variance/min-max clamp, motion weighting and temporal blend are retained. The FS source operates on RGB and a single colour history; unlike the compute variant, it does not require a separate packed YCoCg/luma history or pre-exposure uniform.

Explicit port changes:

1. GLSL ES 3.20/Vulkan resource declarations become ES 3.00/Three uniforms and a fullscreen triangle.
2. ES 3.1 `textureGather` is reproduced using four bounded `texelFetch` operations with identical gather component order and clamp-to-edge behavior. Texture-neighbour reads in Upscale are bounded at viewport edges.
3. Depth/sampler arithmetic uses high precision for WebGL2; the unused camera-only fallback converts OpenGL depth from [0,1] to [-1,1]. The active path receives the complete raw signed NDC motion field.
4. The otherwise-unused Convert alpha channel carries PolyShade's local geometry-history rejection, consumed as an extra per-pixel reset in Upscale. This is an integration extension to the actual SGSR2 shader, not a substitute spatial/temporal filter. The regular history weights are retained outside rejected pixels.
5. Scale/variance parameters follow Qualcomm's GLES sample. The still-camera count compares actual rendered jittered matrices; jitter changes are not mistaken for identical frames.

Qualcomm's license notices are preserved in the source and distributed bundle. See [third-party notices](../THIRD_PARTY_NOTICES.md) and the [full BSD license](../src/vendor/sgsr2/LICENSE). WebGPU/compute and the three-pass algorithm were not ported.
