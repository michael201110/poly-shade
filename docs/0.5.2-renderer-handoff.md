# PolyShade 0.5.2: high-count swarm hot switching

This patch closes the 500-car hot-toggle limitation recorded in the 0.5.1
performance report. It coordinates with **PolyBot bridge 0.1.49**.

Two ownership problems were found:

1. PolyBot interpreted source unavailability as a worker crash and rebuilt
   hundreds of native ghost cars. It now hands the unchanged packed replay
   arrays to its existing standalone instanced worker, then returns to the
   shared renderer when API v1 becomes ready. Its replay owner retains the
   playback clock, leader and controls.
2. Three r181's WebGPU backend `dispose()` clears texture helpers but does not
   destroy the device that PolyShade created. PolyShade now explicitly destroys
   that owned device **after** retiring its caches and renderer. Initialization
   cancelled before completion also retires the resulting device. The disposed
   guard prevents deliberate retirement from becoming a device-loss error.

No shader, quality setting, instance geometry, interpolation, sample format,
replay recording, physics or training semantics changes. The optional API v1
contract remains unchanged. Standalone native PolyTrack use remains supported.

| Bridge | PolyShade | Result |
|---|---|---|
| 0.1.49 | 0.5.2 | Complete handoff and owned-device cleanup fixes |
| 0.1.49 | 0.5.0/0.5.1 | Packed handoff; upgrade PolyShade for device retirement |
| 0.1.48 | 0.5.2 | Device cleanup only; old bridge fallback is unchanged |
| 0.1.49 | Uninstalled/disabled | Existing standalone instanced worker |

Install both updates for the complete fix. Versions 0.5.1 and 0.1.48 remain
immutable historical releases. See PolyBot's `docs/swarm-renderer-handoff.md`
for handoff ownership and crash-fallback details.

## Verification (18 October 2026)

- `npm run check`: **93/93** tests, including device disposal ordering,
  idempotence and suppression of deliberate-retirement error reporting.
- `npm run verify:webgpu`: pass on Edge/T500, all existing resize, temporal,
  material, moving-car, debug and deliberate device-loss checks; zero unexpected
  errors. Active-device loss still reports failure; normal disable does not.
- PolyBot: **35/35 Node renderer tests** and **477/477 Python tests**. Python
  verification used CPU with BLAS/OpenMP threads limited to one to avoid
  competing with the GPU fixture; training was not started.
- Actual Edge PML: **three complete off/on cycles with 500 green recordings**,
  one paused and two moving. Both directions reached their ready instanced
  worker backend; all 500 recordings and the fixed leader stayed loaded.
- Paused at **3.000 seconds**: all 500 positions had **zero numeric difference**
  in shared → standalone → shared captures; pause state and leader were unchanged.
- A test-only wrapper counted native `createCar` calls throughout the cycles:
  **one**, the camera/audio leader. No native fallback swarm was reconstructed.
- No console errors during the live cycles. JS heap snapshots after the three
  returns to shared rendering were approximately **798 → 490 → 287 MB** with
  normal garbage collection; these are snapshots, not an allocation-rate study.
- All 34 protected champion/checkpoint hashes remain unchanged.

[Live handoff results](verification/0.5.2/handoff.json) and
[GPU lifecycle results](verification/0.5.2/webgpu.json).

Switching still initializes the destination renderer and warms its resources;
this is not a promise of zero frame-time spikes during a switch. Renderer-local
temporal/skid histories restart. The previous unbounded native-object fallback
and tab stall were not reproduced in the three cycles.

The first GPU test run exposed false Three device-loss logs during intentional
retirement; fixed in the renderer's retirement callback rather than filtering
those errors out of the test. An external leaderboard polling connection also
held the old harness's `networkidle` wait open; the harness now awaits its
version-pinned static game assets directly. The complete GPU check then passed.
